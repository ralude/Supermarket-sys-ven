## Decisiones aplicadas

- La migracion `0001` crea el esquema relacional de catalogo, monedas, ventas y caja ya implementado; identidad e inventario operativo conservan su diferimiento a las fases 11 y 6.
- Cada migracion aplicada conserva version, nombre, checksum y timestamp UTC en `schema_migrations`; una alteracion posterior del archivo se rechaza.
- Antes de migrar una base existente se crea un snapshot consistente con SQLite en el directorio configurado y se conservan cinco respaldos por defecto.
- El arranque valida integridad y claves foraneas. Ante una migracion o validacion fallida, se restaura el respaldo verificado; no existen migraciones `down` destructivas.

## Criterio de salida

Una base nueva y una base existente pueden avanzar de manera reproducible, y una migracion fallida puede recuperarse desde un backup verificado.
