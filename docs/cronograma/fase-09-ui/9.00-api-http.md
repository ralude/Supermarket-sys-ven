# Sub-fase 9.00: API HTTP y composición

- **Fase:** [Fase 9 - UI](./README.md)
- **Estado:** Pendiente

## Objetivo

Componer casos de uso y adaptadores detrás de contratos HTTP versionados antes de construir pantallas operativas.

## Prerrequisito

Debe estar completado el [gate de seguridad antes de UI operativa](../gate-seguridad-pre-ui.md).

Mientras la Fase 8 esté suspendida, la composición fiscal permitida es
exclusivamente `FiscalPrinterFake`. El contrato HTTP debe exponer de forma
inequívoca que la capacidad fiscal está en modo simulado; las rutas no detectan
hardware ni importan SerialPort, codecs o SDK de proveedor.

## Tareas

- [ ] Componer repositorios, UnitOfWork, autorización, auditoría, reloj e IDs en `apps/server`.
- [ ] Exponer rutas `/api/v1` que solo validen, adapten y deleguen en casos de uso.
- [ ] Construir `ActorContext`, correlation ID e idempotency key desde HTTP.
- [ ] Mapear errores globalmente a `application/problem+json` sin detalles internos.
- [ ] Configurar logging estructurado y redacción mínima en la frontera.
- [ ] Publicar contratos de comandos, queries y respuestas usados por React.
- [ ] Agregar pruebas de contrato HTTP para éxito, error, autorización e idempotencia.

## Criterio de salida

La UI dispone de una API versionada, autenticada y probada sin reglas de negocio en rutas ni composición dentro del renderer.
