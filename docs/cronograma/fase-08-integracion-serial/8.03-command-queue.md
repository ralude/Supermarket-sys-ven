# Sub-fase 8.03: Coordinación single-flight

- **Fase:** [Fase 8 - Integración serial](./README.md)
- **Estado:** Pendiente
- **Prerequisito:** codec 8.02 verificado

## Objetivo

Garantizar una sola solicitud-respuesta en vuelo y una sola operación fiscal por
dispositivo, sin crear una cola durable de comandos no idempotentes.

## Tareas

- [ ] Escribir pruebas de exclusión entre factura, nota de crédito, X, Z,
  reconciliación y consultas de salud.
- [ ] Implementar FIFO acotada en memoria por dispositivo, sin prioridad que
  interrumpa una sesión fiscal abierta.
- [ ] Mantener una sesión fiscal desde apertura hasta cierre/cancelación; no
  intercalar status o heartbeat salvo que el protocolo lo permita expresamente.
- [ ] Rechazar nueva operación cuando exista un documento/reporte ambiguo,
  recuperación pendiente, equipo incompatible o cola completa.
- [ ] Registrar por solicitud `connectionEpoch`, etapa del comando y fronteras
  `QUEUED`, `WRITE_NOT_INVOKED`, `WRITE_INVOKED`, `OS_DRAINED`,
  `RESPONSE_STARTED` y `RESPONSE_VALIDATED` para clasificar evidencia, sin
  confundirlas con emisión. `QUEUED` describe posición en la cola;
  `WRITE_NOT_INVOKED` es la única afirmación negativa sobre el dispatch local.
- [ ] Permitir cancelación de cola solo antes de invocar `write()`. SerialPort
  no permite observar con certeza el «primer byte»; una vez invocado `write`,
  cancelar la espera no cancela el I/O ni vuelve seguro el reenvío.
- [ ] Descartar respuestas tardías de otro epoch, secuencia o comando y llevar
  la operación afectada a recuperación.
- [ ] Cerrar limpiamente: dejar de aceptar trabajo, terminar solo lo que el
  protocolo permita, cerrar el puerto y conservar como ambiguo lo no confirmado.
- [ ] Probar saturación, concurrencia, disconnect/reconnect y reinicio del
  proceso en cada frontera temporal.

## Persistencia

La cola y las tramas viven en memoria. Antes de enviar, la aplicación persiste
el estado del agregado y su intento según el flujo creado en Fase 7. Tras un
reinicio se enumeran documentos y reportes recuperables; nunca se carga una
cola de bytes para reproducirla. El ledger y outbox registran hechos del negocio,
no actúan como spooler de la impresora.

## Criterio de salida

No se intercalan comandos, no hay dos owners del dispositivo y ningún reinicio
reproduce bytes automáticamente. La evidencia de etapa y conexión permite a
8.04 decidir entre retry seguro, reconciliación o intervención.
