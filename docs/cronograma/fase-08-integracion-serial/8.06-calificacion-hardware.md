# Sub-fase 8.06: Calificación del primer perfil con hardware

- **Fase:** [Fase 8 - Integración serial](./README.md)
- **Estado:** Pendiente
- **Prerequisito:** estado 8.05 verificado

## Objetivo

Demostrar que la primera combinación declarada funciona con hardware fiscal
real y con el artefacto Windows que se instalará, no solo con mocks, simulador o
modo de desarrollo. Esta calificación estabiliza las piezas compartidas, pero no
cierra la Fase 8 hasta repetir la evidencia con el segundo perfil.

## Matriz mínima

- Windows 11 x64 como base. Windows 10 x64 solo para ediciones LTSC dentro de
  ciclo o equipos con ESU activo que el producto haya aprobado expresamente.
- Cada modelo, firmware, interfaz USB/RS-232 y adaptador físico declarado.
- Runtime Node/Electron y, cuando el perfil sea serial, versión exacta de
  SerialPort.
- Aplicación empaquetada con binding nativo disponible fuera de ASAR cuando
  corresponda, instalación limpia y usuario sin herramientas de desarrollo.

## Tareas

- [ ] Preparar una unidad de laboratorio controlada y usar modo de entrenamiento
  cuando el fabricante lo ofrezca. Confirmar y documentar para la combinación
  concreta si el paso a modo fiscal es irreversible. Prohibir pruebas
  destructivas en producción; una prueba que requiera modo fiscal necesita plan
  escrito del representante o servicio autorizado y presupuesto de memoria/Z.
- [ ] Ejecutar golden path de identidad, factura, nota de crédito, X, Z y cada
  capacidad incluida en el manifiesto, verificando números y contadores reales.
- [ ] Verificar el documento impreso contra el checklist aprobado en 8.00 por
  asesoría tributaria y representante, con vigencia de SNAT/2011/00071,
  SNAT/2018/0141 y normas relacionadas confirmada para el piloto: secuencia,
  fecha/hora, emisor,
  comprador/RIF cuando aplique, ítems, cantidades, bases/tasas, exento/
  percibido, total, logo/registro fiscal y relación de notas con original.
- [ ] Verificar moneda/equivalente, tipo de cambio e IGTF contra sus fuentes
  normativas vigentes y la condición tributaria de la tienda; nunca contra un
  porcentaje hardcodeado o tomado solo del protocolo PNP.
- [ ] Comparar totales y redondeo calculados por firmware con los esperados por
  aplicación y validar marcas de X, documentos no fiscales y copias de auditoría.
- [ ] Probar desconexión USB/serial y pérdida de energía antes, durante y después
  de escritura, drain, respuesta y cierre de documento.
- [ ] Probar sin papel, tapa abierta, busy/procesando, memoria casi llena/llena,
  documento abierto, cierre Z requerido y respuesta corrupta cuando el equipo o
  simulador permita inyectarlos.
- [ ] Probar reinicio de aplicación, crash del owner, cambio de COM, sustitución
  del equipo, lock de segundo proceso y recuperación posterior.
- [ ] Verificar coexistencia con el DCTD en la topología autorizada sin ocupar ni
  alterar su canal, configuración o transmisión.
- [ ] Ejecutar soak test acotado y comprobar que no crecen listeners, buffers,
  handles, cola ni tiempos de respuesta de forma no explicada.
- [ ] Instalar el artefacto en Windows limpio y repetir `list/open/probe`, flujo
  fiscal y recuperación; repetir después de cambiar Node, Electron, SerialPort,
  arquitectura o packaging.
- [ ] Registrar resultados, evidencia redactada, desviaciones, modelo/firmware
  exactos y firma técnica del fabricante/representante cuando esté disponible.
- [ ] Definir y registrar presupuesto de cierres Z. No ejecutar Z reales en soak
  loops ni consumir memoria fiscal sin autorización escrita del representante.
- [ ] Crear runbooks de asignación COM, diagnóstico, reemplazo, contingencia,
  reconciliación, escalamiento y rollback solo de aplicación/driver/configuración.
  Nunca revertir documento, memoria, Z o firmware; firmware queda en manos del
  representante o servicio autorizado.
- [ ] Ejecutar `pnpm pipeline` y actualizar cronograma, matriz y documentación
  pública para declarar únicamente las combinaciones aprobadas.

## Criterio de salida

Todas las pruebas obligatorias del primer perfil pasan con mocks/fakes deterministas, simulador
oficial cuando exista y hardware real desde un build instalable. Cada falla
incierta conserva evidencia y bloqueo sin duplicar efectos. El manifiesto y
runbook permiten a soporte determinar de forma objetiva si una instalación está
soportada. El resultado habilita 8.07; no declara todavía completada la fase.
