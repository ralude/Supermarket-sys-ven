# Sub-fase 8.01: Transporte SerialPort

- **Fase:** [Fase 8 - Integración serial](./README.md)
- **Estado:** Pendiente
- **Prerequisito:** [Gate 8.00](./8.00-gate-evidencia-proveedor.md) completado

## Objetivo

Implementar en `packages/drivers/hardware` un transporte de bytes serial
reutilizable, sin comandos fiscales, cálculos, interpretación de status ni
dependencias en el renderer.

## Contrato mínimo

- Configuración explícita por perfil: `path`, `baudRate`, `dataBits`,
  `stopBits`, `parity`, control de flujo y límites temporales.
- `autoOpen: false`, `lock: true`, listeners permanentes de `error` y `close`
  registrados antes de abrir.
- Ciclo de vida idempotente y observable del puerto: `CLOSED`, `OPENING`,
  `OPEN`, `CLOSING`, `DISCONNECTED` y `QUARANTINED`; una instancia nueva
  después de reconectar. `PROBING`, compatibilidad y `READY` pertenecen al
  adaptador fiscal, no al transporte de bytes.
- Lectura y escritura como `Buffer`; ningún supuesto de línea, texto, STX/ETX,
  ACK/NAK o checksum.
- `write` + backpressure de stream + `port.drain()` con deadlines propios. El
  resultado solo representa progreso del transporte, nunca confirmación fiscal.
- `connectionEpoch` para descartar callbacks y bytes tardíos de una conexión
  anterior.
- Deadlines que marcan abandono de espera sin afirmar que cancelaron el I/O
  nativo. Un puerto/worker atascado queda en cuarentena hasta terminarlo y
  comprobar la liberación del lock.
- Errores públicos estables y logs estructurados sin payload fiscal, secretos ni
  stack trace hacia el cliente.

  `@serialport/bindings-cpp` por separado salvo defecto demostrado.
- [ ] Revisar `onlyBuiltDependencies`/`allowBuilds` de pnpm para la versión
  transitiva exacta de bindings, comprobar que ningún script nativo fue ignorado
  y validar binario, firma/hash cuando exista y arquitectura empaquetada.
- [ ] Escribir pruebas del ciclo `create -> listeners -> open -> write -> drain
  -> read -> close` mediante `SerialPortMock`/`MockBinding` y un fake de
  transporte para deadlines deterministas.
- [ ] Probar aperturas fallidas, doble apertura/cierre, puerto ocupado, error no
  manejado, desconexión física simulada y cancelación deliberada.
- [ ] Probar backpressure, escritura parcial, timeout de apertura/escritura/
  drain/primer byte/inter-byte/respuesta y callbacks tardíos entre epochs.
- [ ] Probar que un deadline implementado con espera competitiva no crea otra
  instancia mientras `open`, `write` o `drain` anteriores puedan seguir
  vivos; calificar el mecanismo de terminación/reinicio elegido en 8.00.
- [ ] Implementar el adaptador detrás de un export público; no importar
  internals de otro paquete ni filtrar tipos de SerialPort a aplicación.
- [ ] Rechazar operaciones de transporte mientras el puerto no esté `OPEN`,
  aunque la librería pueda encolarlas antes de abrir. `READY` lo valida el
  adaptador fiscal.
- [ ] Usar `SerialPort.list()` solo para diagnóstico/configuración asistida. No
  seleccionar el primer COM ni considerar VID/PID/serial como identidad fiscal.
- [ ] Evitar `flush()` en operación normal y cambios DTR/RTS salvo exigencia
  explícita del manual seleccionado.
- [ ] Agregar prueba de lock/exclusión con puerto virtual o dos procesos y smoke
  de Windows x64 en el runtime elegido.

## Criterio de salida

El mismo transporte supera pruebas de chunking, backpressure, deadlines,
desconexión y exclusividad sin conocer el dialecto fiscal. No existe una ruta
desde renderer al puerto y todo timeout posterior a invocar `write()` conserva
evidencia suficiente para que la capa superior lo trate como ambiguo.
