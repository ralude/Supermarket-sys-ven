# Sub-fase 8.09: Calificación cruzada y cierre

- **Fase:** [Fase 8 - Integración serial](./README.md)
- **Estado:** Pendiente
- **Prerequisito:** segundo adaptador [8.08](./8.08-adaptador-segundo-perfil.md) verificado

## Objetivo

Calificar el segundo perfil con hardware real y demostrar que el contrato,
transporte, selección de perfil, recuperación y distribución siguen funcionando
con las dos combinaciones exactas sin contaminación entre proveedores.

## Tareas

- [ ] Ejecutar en una unidad HKA/ACLAS controlada la matriz HIL completa de
  [8.06](./8.06-calificacion-hardware.md), adaptada al transporte o SDK oficial
  del segundo perfil, incluidos golden path, checklist impreso, caos, soak,
  lock/ownership, presupuesto de Z, reinicio y reconciliación.
- [ ] Verificar factura, nota de crédito, X, Z, impuestos, moneda, IGTF,
  redondeo, números y contadores contra las fuentes y el manifiesto HKA.
- [ ] Probar falta de papel, tapa abierta, busy, memoria, sesión abierta,
  desconexión y pérdida de energía en todas las fronteras que el equipo permita.
- [ ] Verificar coexistencia con su DCTD y que el driver no ocupa, configura ni
  transmite por el canal reservado.
- [ ] Instalar el build Windows limpio y repetir identidad, operación y
  recuperación con el transporte o SDK empaquetado.
- [ ] Ejecutar regresión completa del primer perfil PNP con el mismo build final.
- [ ] Probar selección explícita y fallo cerrado al conectar cada equipo con el
  perfil equivocado, cambiar COM o interfaz cuando aplique, o sustituir
  modelo/firmware.
- [ ] Confirmar que ambos adaptadores superan las mismas aserciones semánticas
  en simulador y, por separado, sus suites HIL autorizadas; cada uno conserva
  vectores y manifiestos independientes y ningún consentimiento simulado
  habilita comandos sobre hardware.
- [ ] Registrar dos expedientes HIL completos con fabricante, modelo, firmware,
  protocolo/SDK, interfaz, DCTD, Windows, runtime y versiones del artefacto.
- [ ] Crear runbooks diferenciados de instalación, diagnóstico, reemplazo,
  contingencia, reconciliación y escalamiento para PNP y HKA/ACLAS.
- [ ] Revalidar autorización, registro del integrador, regulación y soporte de
  ambos perfiles en la fecha de liberación.
- [ ] Ejecutar `pnpm pipeline` y actualizar cronograma, ADR, matriz y alcance
  público para declarar únicamente las dos filas aprobadas.

## Criterio de salida

Las dos combinaciones exactas superan el mismo contrato observable, su propia
evidencia de protocolo o SDK y HIL desde un build instalable. Una falla o evidencia
faltante en cualquiera mantiene la Fase 8 abierta. El cierre no declara soporte
para toda la marca ni para modelos o firmware fuera de las dos filas.
